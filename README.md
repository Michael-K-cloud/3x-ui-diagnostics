3x-ui-diagnostics
Скрипты для диагностики сервера 3x-ui
🖥️ Система диагностики сервера (3x-ui-diagnostics)
Удобная система управления и диагностики VPS-серверов на базе панели 3X-UI. Представляет собой набор bash-скриптов с интерактивным меню, запускаемым командой menu.
📋 Возможности
🔎 Диагностика сервера (подменю пункта 1):
📊 Отчёт о состоянии сервера — статус панели, целостность базы данных (PRAGMA integrity_check) и счётчики таблиц, CPU, память, диск, uptime, критические ошибки за 24 часа, отдельный поиск ошибок malformed / disk I/O (включая WARNING-приоритет, которым панель пишет сбои БД)
🛡 WAL-сторож — фоновый контроль базы x-ui каждые 5 минут (cron): размер WAL/SHM, «удалённые» файловые дескрипторы панели, ошибки БД за 5 минут. Подменю: статус, лог, включить, выключить, перезапустить. Скрипт только наблюдает, в базу не пишет. Лог /root/wal-watch.log
📈 htop — диспетчер задач
📌 Эталон сервера — снапшот опорного состояния (целостность и счётчики БД, настройки панели без секретов, sha256 конфигов nginx, порты, jail-ы fail2ban, статус сторожа); сохранение и сравнение «до/после» любых изменений. Файл /root/scripts/etalon/etalon.txt
🌐 HTML-отчёты — создание страницы отчёта и ссылки на неё (см. ниже)
🔃 Перезагрузка сервера — с предупреждением и подтверждением yes
🛠 Управление панелью X-UI и Xray — перезапуск, детальный статус, список слушаемых портов
🔌 Управление портами — проверка, открытие, закрытие через UFW с защитой от случайного удаления SSH
📋 Работа с логами — отсортированные логи (ERROR/WARNING/INFO) за период: последний час / 6 часов / любое количество часов числом; очистка journald; HTML-версия логов ссылкой
🛡 Отчёт по fail2ban — активные блокировки, статистика, ID клиентов 3X-UI
🚀 Запуск родного меню x-ui
🌐 HTML-отчёты (ссылки вместо «простыней» текста)
Любой отчёт (состояние сервера, WAL-сторож, сравнение с эталоном, fail2ban, логи за N часов) можно сгенерировать как HTML-страницу и получить ссылку — удобно для Telegram-бота: в чат приходит короткая сводка + ссылка, полный отчёт открывается в браузере.
Генератор: bash /root/scripts/report.sh {status|wal|etalon|fail2ban|logs} [часы]
Страницы складываются в /var/www/report/<секрет>/ (секретная часть URL создаётся автоматически при первом запуске и хранится в /root/scripts/.env, права 600 — посторонний не угадает адрес отчёта)
Ссылка вида: https://<ваш-домен>/report/<секрет>/latest-status.html
Хранится не более 30 копий каждого типа отчёта, старые удаляются автоматически
Настройка nginx (один раз на сервере, вручную)
В server-блок основного домена (тот, что обслуживает HTTPS) добавить:
nginx
123456
Затем обязательно: бэкап конфига → nginx -t → systemctl reload nginx. При ошибке nginx -t — откатить бэкап. На серверах с архитектурой nginx-stream (x-ui-pro) правится vhost основного домена в sites-available; stream.conf не трогать.
✨ Особенности
🕐 Все даты и время отображаются в московском часовом поясе (UTC+3)
🎨 Единообразное оформление: розовые заголовки меню, белые заголовки отчётов, зелёные пункты выбора
🔍 Отчёт по fail2ban показывает ID клиентов 3X-UI (из JSON в базе данных)
🛡 Защита от случайных действий (двойные подтверждения, защита SSH-порта)
📱 Удобное навигационное меню с возвратом по Enter
🔒 Все обращения к живой базе данных — только для чтения (mode=ro&immutable=1), безопасно при работающей панели

🔒 Безопасность
Скрипты не содержат конфиденциальной информации (паролей, ключей, токенов)
Репозиторий можно сделать публичным без риска утечки данных
Секретная часть URL отчётов хранится в /root/scripts/.env (права 600), в репозиторий не попадает
WAL-сторож и эталон обращаются к базе данных только для чтения (immutable=1) — безопасно на работающей панели
При использовании приватного репозитория потребуется Personal Access Token
