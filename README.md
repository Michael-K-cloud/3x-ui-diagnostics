Скрипты для диагностики сервера 3x-ui


# 🖥️ Система диагностики сервера (3x-ui-diagnostics)

Удобная система управления и диагностики VPS-серверов на базе панели **3X-UI**. Представляет собой набор bash-скриптов с интерактивным меню, запускаемым командой `menu`.

## 📋 Возможности

- 🔎 **Диагностика сервера** (подменю пункта 1):
  - 📊 **Отчёт о состоянии сервера** — статус панели, **целостность базы данных (`PRAGMA integrity_check`) и счётчики таблиц**, CPU, память, диск, uptime, критические ошибки за 24 часа, **отдельный поиск ошибок `malformed / disk I/O` (включая WARNING-приоритет, которым панель пишет сбои БД)**
  - 🛡 **WAL-сторож** — фоновый контроль базы x-ui каждые 5 минут (cron): размер WAL/SHM, «удалённые» файловые дескрипторы панели, ошибки БД за 5 минут. Подменю: статус, лог, включить, выключить, перезапустить. Скрипт только наблюдает, в базу не пишет. Лог `/root/wal-watch.log`
  - 📈 **htop** — диспетчер задач
  - 📌 **Эталон сервера** — снапшот опорного состояния (целостность и счётчики БД, настройки панели без секретов, sha256 конфигов nginx, порты, jail-ы fail2ban, статус сторожа); сохранение и сравнение «до/после» любых изменений. Файл `/root/scripts/etalon/etalon.txt`
  - 🌐 **HTML-отчёты** — создание страницы отчёта и ссылки на неё (см. ниже)
- 🔃 **Перезагрузка сервера** — с предупреждением и подтверждением `yes`
- 🛠 **Управление панелью X-UI и Xray** — перезапуск, детальный статус, список слушаемых портов
- 🔌 **Управление портами** — проверка, открытие, закрытие через UFW с защитой от случайного удаления SSH
- 📋 **Работа с логами** — отсортированные логи (ERROR/WARNING/INFO) за период: **последний час / 6 часов / любое количество часов числом**; очистка journald; HTML-версия логов ссылкой
- 🛡 **Отчёт по fail2ban** — активные блокировки, статистика, ID клиентов 3X-UI
- 🚀 **Запуск родного меню x-ui**

## 🌐 HTML-отчёты (ссылки вместо «простыней» текста) — БЕЗ правки nginx

Любой отчёт (состояние сервера, WAL-сторож, сравнение с эталоном, fail2ban, логи за N часов) можно сгенерировать как HTML-страницу и получить ссылку — удобно для Telegram-бота: в чат приходит короткая сводка + ссылка, полный отчёт открывается в браузере.

- Генератор: `bash /root/scripts/report.sh {status|wal|etalon|fail2ban|logs} [часы]`
- **Правка конфигов nginx НЕ требуется.** Отчёты пишутся прямо в каталог сайта-заглушки (webroot), который nginx уже отдаёт как статику: например `/var/www/html/<секрет>/latest-status.html`
- Каталог webroot определяется автоматически из vhost-конфига основного домена (директива `root`); переопределение — строка `REPORT_WEBROOT=/путь` в `/root/scripts/.env`
- Секретная часть URL (`REPORT_PATH`, 12 hex) создаётся автоматически при первом запуске и хранится в `/root/scripts/.env` (права 600) — посторонний адрес отчёта не угадает
- Ссылка вида: `https://<ваш-домен>/<секрет>/latest-<тип>.html?v=<метка_времени>` (суффикс `?v=` защищает от показа закэшированной версии)
- Хранится не более 30 копий каждого типа отчёта, старые удаляются автоматически
- Если webroot не определён — файлы пишутся в `/var/www/report/<секрет>/` и скрипт честно предупреждает, что ссылка открываться не будет (нужно указать `REPORT_WEBROOT`)

## ✨ Особенности

- 🕐 Все даты и время отображаются в **московском часовом поясе** (UTC+3)
- 🎨 Единообразное оформление: розовые заголовки меню, белые заголовки отчётов, зелёные пункты выбора
- 🔍 Отчёт по fail2ban показывает **ID клиентов 3X-UI** (из JSON в базе данных)
- 🛡 Защита от случайных действий (двойные подтверждения, защита SSH-порта)
- 📱 Удобное навигационное меню с возвратом по Enter
- 🔒 Все обращения к живой базе данных — только для чтения (`mode=ro&immutable=1`), безопасно при работающей панели

## ⚙️ Требования

- **ОС:** Ubuntu 22.04 / 24.04 (проверено)
- **Права:** root
- **Панель:** 3X-UI (установлена)
- **Зависимости:** `sqlite3`, `sysstat` (устанавливаются автоматически)
- **Дополнительно:** `fail2ban` (для отчёта по блокировкам), `htop` (для диспетчера задач, ставится отдельно: `apt install -y htop`)

## 🚀 Быстрая установка (одной командой)

```bash
wget --inet4-only --timeout=30 --tries=3 -qO /tmp/diag.tar.gz https://codeload.github.com/Michael-K-cloud/3x-ui-diagnostics/tar.gz/refs/heads/main && tar -xzf /tmp/diag.tar.gz -C /tmp && bash /tmp/3x-ui-diagnostics-main/install.sh
```

Команда скачивает весь репозиторий **одним архивом** с `codeload.github.com` и запускает установщик из распакованной папки (дальше сеть не нужна).

> ⚠️ **Почему не `raw.githubusercontent.com`:** этот домен отдаётся с четырёх IP Fastly (185.199.108–111.133), и из сетей некоторых серверов один из них недоступен (проверено 25.09.2026: `185.199.111.133` — таймаут с сервера FI). DNS выдаёт адреса в случайном порядке → пофайловое скачивание случайным образом обрывается. `codeload.github.com` работает на другой инфраструктуре и лишён этой проблемы. Флаг `--inet4-only` обязателен: исходящий IPv6 на серверах может не работать.

Альтернативная команда (короче, но может потребовать повторного запуска из-за случайных IP Fastly):

```bash
bash <(wget --inet4-only --timeout=20 -qO- https://raw.githubusercontent.com/Michael-K-cloud/3x-ui-diagnostics/main/install.sh)
```

После установки запустите:
```bash
menu
```

Повторный запуск установщика = обновление скриптов (cron, лог сторожа, `.env` и эталон не затрагиваются).

## 🔧 Ручная установка


###  1. Установка зависимостей
```bash
apt update && apt install sqlite3 sysstat -y
```
###  2. Скачивание всего репозитория одним архивом
```bash
wget --inet4-only --timeout=30 --tries=3 -qO /tmp/diag.tar.gz https://codeload.github.com/Michael-K-cloud/3x-ui-diagnostics/tar.gz/refs/heads/main
tar -xzf /tmp/diag.tar.gz -C /tmp
```
###  3. Установка из распакованной папки (без сети)
```bash
bash /tmp/3x-ui-diagnostics-main/install.sh
```
Установщик сам создаст `/root/scripts`, скопирует файлы, проверит, что они непустые, выставит права и создаст команду `menu`.

###  4. Запуск
```bash
menu
```

## 📖 Использование

| Команда | Описание |
|---------|----------|
| `menu` | Запуск главного меню |
| `bash /root/scripts/system_report.sh` | Отчёт о состоянии сервера напрямую |
| `bash /root/scripts/fail2ban.sh` | Отчёт по fail2ban напрямую |
| `bash /root/scripts/baseline.sh save` | Сохранить текущее состояние как эталон |
| `bash /root/scripts/baseline.sh compare` | Сравнить текущее состояние с эталоном |
| `bash /root/scripts/report.sh status` | HTML-отчёт о состоянии + ссылка |
| `bash /root/scripts/report.sh logs 12` | HTML-отчёт логов за 12 часов + ссылка |
| `tail -f /root/wal-watch.log` | Живой лог WAL-сторожа |

### Формат строки лога WAL-сторожа

```
<дата> <время UTC> pid=<PID панели> wal=<байт|-> shm=<байт|-> fd=<clean|DELETED-HANDLE> err5m=<число>
```

Тревожные признаки: `fd=DELETED-HANDLE` (панель держит удалённый файл журнала), `err5m>0` (ошибки БД за 5 минут), `wal=-` при работающей панели.

## 🔒 Безопасность

- Скрипты **не содержат** конфиденциальной информации (паролей, ключей, токенов)
- Репозиторий можно сделать **публичным** без риска утечки данных
- Секретная часть URL отчётов хранится в `/root/scripts/.env` (права 600), в репозиторий не попадает
- WAL-сторож и эталон обращаются к базе данных **только для чтения** (`immutable=1`) — безопасно на работающей панели
- При использовании приватного репозитория потребуется Personal Access Token
